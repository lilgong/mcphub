# MCPHub v2.0

This release consolidates the v2 catalog deployment and the operational fixes used
with MCP-Atlas and Toolathlon. MCPHub remains independent of benchmark repositories.

## Capabilities

- Public MCPs execute in Hub; scoped STDIO services execute in authenticated,
  isolated space workers. Benchmarks retain ownership of task containers and callbacks.
- Account/version connections and task connections share account management,
  encrypted credentials and live permission checks. Account admission can be disabled
  without interrupting an already leased run.
- HTTP and gRPC SDK forwarding preserve upstream timeout budgets, encoded resource
  paths, response bodies and caller-side redirect handling. GitHub forwarding includes
  shared scheduling, throttling observations and bounded redirect handling.
- Relay lifecycle is managed from the dashboard. Network and request budgets remain
  configurable per upstream group. Public arXiv queries and Overpass requests support
  persistent response caching; invalid/error responses are not cached as successes.
- Durable batched auditing retains sanitized failure details. Yibu usage statistics
  aggregate by month, MCP and upstream key fingerprint/suffix, including historical keys.
- Call-detail searches cover complete source logs before filtering and pagination.
  A bounded process-local metadata index reads append-only updates incrementally;
  source rotation/truncation rebuilds the affected index. Dashboard refreshes do not overlap.
- Group permissions, account controls, date filtering and secret visibility use the
  unified dashboard controls. Deleted registrations do not inflate current group grants.

## Deployment

Use the root `compose.yaml` and `.env.example`, following
[deployment instructions](../../deploy/v2/README.md). Keep existing `.env`, runtime
volumes, PostgreSQL data, encrypted credentials and credential encryption keys.
Never overwrite an existing installation's `.env` with the example file.

The root Dockerfile builds Hub and workers without requiring an Atlas checkout.
Imported MCP packages and task adapters remain separate artifacts; this Git tag does
not distribute operator credentials, runtime logs or benchmark data.

An image rebuild and deployment are required to apply source changes. Creating this
release commit/tag does not update or restart an existing deployment. Hub recreation
interrupts its active connections and managed Relay; schedule it after active runs.

## Validation

Release validation on 2026-11-26 passed backend/frontend builds, distribution
verification, ESLint and all 88 MDX pages. Jest passed 306 suites / 2,717 tests.
Python Relay tests passed 260 tests with one existing conditional skip. Test infrastructure isolates configuration and audit files from deployment
credentials. A Git tag identifies source, not the image currently running on a server.
